# Save module

Version 1.3 writes named save objects with their full string ID and sets the save schema to 2. It uses the existing `save` file, BinaryFormatter container on native platforms and JSON on WebGL. When a named key is first read, an unclaimed matching legacy entry is migrated and its string ID is persisted on the next successful save.

Use a stable explicit string key for new models. `GetSaveObject<T>()` defaults to the full type name, so preserve the original ID when renaming a class. If migrating a save across runtimes with different historical hash values, supply the original hash using `GetSaveObject<T>(key, legacyHash)`. A hash-only legacy save cannot distinguish keys that collided before migration. Explicit integer keys remain available for existing callers.

## Calling the API

- Mutate save objects and call `MarkAsSaveIsRequired()` on Unity's main thread.
- `Save()` captures a snapshot on the main thread and queues IO when the active
  wrapper supports background writes. Returning means scheduled, not persisted.
- `Save(useThreads: false)` waits for previous writes and attempts its write before
  returning. Ordinary save failures are logged and leave the save dirty for retry.
- `SaveChecked()` always writes, waits for earlier requests, and throws on failure.
  Use it when a purchase or claim must know whether persistence succeeded.
- `SaveCustom`, `PresetsSave`, `DeleteSaveFile`, and `GetGlobalSave` wait behind
  queued writes. Custom/preset writes do not acknowledge the live save's dirty state.

Flush and JSON capture happen before IO. A snapshot owns separate containers with
captured JSON and has no references to live `ISaveObject` instances. Only a successful
write of the current revision clears dirty; mutations marked during an older write
remain dirty. Queued requests continue after a failed ordinary write.

The default wrapper uses the same checked serializer for every controller write:
write a sibling `.pending` file, flush it, then replace/move it into place. A failed
serialization leaves an existing destination intact. The serializer's unchecked API
uses the same path and logs errors; its checked API propagates them.

## Lifecycle

`Init` is idempotent, including reentrant calls from `OnSaveLoaded`. The first init's
autosave configuration is retained; later calls do not clear data or start another
receiver/coroutine. Pause, quit, and editor receiver destruction flush synchronously.
Static unload drains queued IO, stops autosave, and removes the receiver without
triggering an extra save from its destruction.

## Verification and limits

`SaveModuleTests` covers ordered writes, snapshot isolation, dirty tracking, failure
and retry, checked barriers, related file operations, receiver lifecycle, and atomic
replacement. `SaveFixtures/BeforeRefactor.bytes` was generated by the original
implementation before editing it, with an integer key and the existing `currency:0`
string key. The tests read it and read newly written files with the original reader.

Gameplay mutations/Flush are main-thread operations. Custom wrappers must propagate
write errors and finish their IO before `Save` returns; they cannot silently swallow
failure or start their own detached writer. Native and browser storage durability is
limited by the platform. The existing WebGL bridge has no durable-write acknowledgement;
Editor tests do not validate browser persistence or mobile filesystem behavior.

Verified in Unity 6000.3.12f1 on 2026-10-08: Save tests 20/20, IAP tests 25/25,
scene smoke tests 4/4. Full EditMode suite: 77/81 passed, with the same four Quest
failures as the pre-change baseline (daily/weekly slot counts, online-time reward
type, and Go button sprite). No new compiler errors or missing scripts were found.
